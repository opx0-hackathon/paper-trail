# 2026-08-24 — /api/state returned 500 for ~20 min

## Symptom

Header badge showed **"cached answers"** on `https://trail.opxz.dev/`
instead of `openai/gpt-oss-20b`. The site loaded, the model was healthy,
but the frontend fell into cached-mode because it could not load its
initial state.

## Impact

Every visitor during the window saw a degraded UI (no starter examples
populated, no live model badge, no session cookie set). Zero data loss.
Duration ≈ 20 min between the repo move and the fix.

## Trace (top-down through the stack)

1. **Browser** — `GET /api/state` returned **500**.
2. **Caddy** — `sudo grep trail.opxz.dev /etc/caddy/Caddyfile` showed the
   block was proxying `/api/*` to `127.0.0.1:8791` (a "next" unit), not
   `:8790` where the main app was healthy.
3. **Systemd** — `systemctl status papertrail-next.service` was active,
   running old code from a moved checkout.
4. **App logs** — `journalctl -u papertrail-next.service` showed
   `sqlite3.OperationalError: table memories has no column named source`.

## Root causes

Two, both structural:

1. **Silent code drift after a repo move.** The moved checkout kept
   running under its old systemd unit and its old Caddy route. Nothing
   noticed that "the live URL" and "the code you edit" had diverged.
2. **No migration path.** `store.py` used `CREATE TABLE IF NOT EXISTS`
   for the schema. That is idempotent for the initial create but **never
   ALTERs**. A newer commit added `source` and `created_at` columns to
   `memories`, and no code applied them to an existing DB.

## Fix (immediate)

- Stopped and removed `papertrail-next.service` and its old checkout.
- Replaced the Caddyfile with a single-line block: `trail.opxz.dev { reverse_proxy 127.0.0.1:8790 }`.
- Backend now serves `web/dist/` itself, so there is no separate static
  root to keep in sync.
- App re-deployed as a single Docker container (`compose.yml`, bound to
  loopback, Caddy in front).
- Wiped the old DB — sessions purge every 24h anyway, so the loss was
  bounded.

## Prevention (structural)

- Numbered SQL migrations in `migrations/` + a boot-time runner in
  `store.py::_migrate`. Old boxes now catch up on next start; the
  `source` column no longer requires manual ALTER.
- `DECISIONS.md` records the migration decision so it does not get
  reverted.
- `deploy.sh` and CI/CD both smoke-test **/api/state**, not just
  `/healthz`. A 500 there fails the deploy — the "next unit" pattern
  cannot silently take over again.
- `/healthz` now checks the DB with `SELECT 1` and returns 503 if it
  fails. Docker's HEALTHCHECK reads this and restarts the container.
- `compose.yml` binds `127.0.0.1:8790` only. Container ports are not
  publicly reachable except through Caddy — one door in, one config to
  keep true.

## Lessons

- A repo move without stopping the old service = two live copies drifting.
  **Always** `systemctl disable --now <old>` before deleting a checkout.
- `IF NOT EXISTS` protects creates, not alters. Any long-lived DB needs
  a migration runner from day one — not "when we outgrow SQLite".
- Smoke tests must hit the endpoint that actually failed, not the one
  that would trivially pass. `/healthz` said `{"ok": true}` throughout
  the incident.
